## 1. `rowingl` shipped misnamed — the port stroke could not play

`xRowing1.kf` lays five segments end to end in one clip. Dumped with their key
times, across every skeleton folder:

```
 0.000- 2.833  rowingidle   oars shipped            (no loop keys)
 3.667-10.533  rowing1      pulling ahead           loop  4.167- 9.833
10.833-13.700  rowingr      one oar                 loop 11.700-13.000
13.733-16.333  rowingr      one oar  <-- AGAIN      loop 14.500-15.833
16.667-19.300  rowslow      pulling ahead, gently   loop 17.467-18.800
```

Two complete, non-overlapping `rowingr` cycles, and **no `rowingl` anywhere in
any of the six files**. A group cannot have two start keys and play both, so one
of those segments was unreachable and the port stroke had no name at all.

This is the `godola1` typo from 2026-10-09 wearing a different hat: a text-key
name that splits or collides, in a clip whose other groups are fine.

### Which one was wrong

The second. `xGondola1.kf` is the only precedent in this package and it orders
its turn segments **right then left** (`gondolar` at 4.5, `gondolal` at 6.333),
so the first `rowingr` block keeps the name and 13.733–16.333 becomes
`rowingl`.

That is an inference from one neighbouring clip, not a reading of the motion —
**if turning feels mirrored in game, the two names want swapping**, which is one
command and no size change. You authored the clip, so you will know on sight.

### `fix_textkeys.py` gained a time window

The existing tool renames every occurrence in a file, which cannot fix a
collision — it just moves it. It now takes `--from` / `--to`, bounds compared
against each key's own time:

```
tools/fix_textkeys.py rowingr rowingl --from 13.72 --to 16.40 <6 files>
```

Bounds are inclusive, so the first attempt used `--from 13.70` and caught the
*first* block's `stop` key at exactly 13.700 — leaving one group with no stop
and the other with two. The tool prints every key it changed with its time,
which is how that was caught in the first pass rather than in game; the window
moved to 13.72 and the next run was clean. The printing is the feature.

`r` → `l` is the same byte length, so all six files are byte-for-byte the same
size as before. Verified: 18 keys, five distinct complete groups, `rowingl` and
`rowingr` both present on **all six** skeleton folders.

**Fix the .blend export too**, or the next export brings it back.

## 2. `check_anims.py` passed the duplicate

The tool collected text keys into a **set**, so two complete cycles under one
name collapsed to a single entry and `rowingr` was reported as healthy on all
skeletons. That is the same blind spot the 10-09 pass fixed for *incomplete*
groups, in the same function, one container choice away: a set cannot count.

It now counts keys and reports any group with more than one start/stop cycle:

```
DUPLICATED groups (two or more segments share one name, so only one is reachable):
  rowingr        2 cycles  [loop start x2, loop stop x2, start x2, stop x2]  animations/xbase_anim/xRowing1.kf
  ... (all six files)
```

### Also: two shipped skeleton folders were never checked

`DEFAULT_SKELETONS` lists four, and this build ships six —
`xbase_anim_female.1st` and `xbase_animkna.1st` are new here and were reported
as *"also present, not checked"*. They are in fact complete and consistent (17
groups each, same as the rest), but that was unverified. Run it with the full
set until the default is widened:

```
tools/check_anims.py . --skeletons xbase_anim,xbase_anim.1st,xbase_anim_female,xbase_animkna,xbase_anim_female.1st,xbase_animkna.1st
```

## 3. An abandoned boat kept its looping sound

`boats_global.lua`'s `onUpdate` guards against either object going invalid:

```lua
if not s.boat:isValid() or not s.player:isValid() then
    session = nil
    if s.player:isValid() then s.player:sendEvent(EV.LEFT, ...) end
    return
end
```

It cleared the session by hand and so **skipped `stopSound`**, which only
`endSession` calls. When the *boat* goes invalid that is harmless — its attached
sound goes with it. But this guard also fires when the **player** goes invalid
while the boat is still there, and then a hull creak started with
`{ loop = true }` is left running on an abandoned boat with nothing holding its
name to stop it.

Same shape as the looping animation that survived a save in the 10-08 build
review, and as the mount script that forgot its group name. Routed through
`endSession`, which guards every step on `isValid` individually and also
re-places the boat properly.

## 4. `getBoundingBox()` guarded in one place, not the other

`hullFromBox` checks for a missing box; `board` did not, three lines after
calling it on the same kind of object:

```lua
local box = target:getBoundingBox()
local reach = T.claimRange + math.max(box.halfSize.x, box.halfSize.y)
```

A static with no renderable geometry would throw from inside an activation
handler. Guarded to match, so which line the object reaches first no longer
decides whether the check exists.

## `check_declorder.py` — the tool the last review asked for

The 10-08 review named this the single highest-value addition to the toolchain,
because the bug class it catches produces no error, no warning, and code that
reads correctly. In Lua a `local` is only in scope *after* its statement, so
code above it silently resolves the name as a **global** — in both directions,
which is why no existing checker sees it:

- `luacheck` parses it; it is valid Lua.
- `globalcheck.py` reports undeclared *reads* — but the code above also
  *writes* the name, which creates the global, so the read is of something that
  exists.
- `check_names.py` gathers declarations for the whole file with no notion of
  position, so the name counts as declared everywhere.

Validation, which matters more than the code:

| run against | result |
|---|---|
| the pre-fix `ridingAnim.lua` (the real historical bug) | **6 findings** at lines 429–461, declared 521 |
| Take a Seat, p37z, Devilish Guar Riding, Cod3x (57 files) | **0** |
| this build, Core + Boats (18 files) | **0** errors, 7 shadowing warnings |

The first run on this build produced three false positives in
`boats_player.lua` — `l10n = L10N` and `settings = { ... }` inside
`I.Settings.registerGroup { ... }`. Those are table **keys**, which look exactly
like assignments. The checker now tracks brace depth and skips a `name =` that
sits inside an unclosed `{`, which is why any mod that registers settings would
otherwise report its own option names. The seven remaining warnings are all
function parameters in test files shadowing a later file-level local — genuine
shadowing, correctly not an error.

## The rowing set

`rowing` was reserved on 10-09 with a documented shape and no clip. The clip
shipped with this build, so it is registered — but **the real group names are
not the ones the stub reserved** (`rowidle` / `rowstroke` / `rowl` / `rowr`), and
the clip carries a fifth segment the stub did not anticipate.

```lua
rowing = {
    base   = "rowingidle",   -- oars shipped
    stroke = "rowing1",      -- pulling ahead, at speed
    slow   = "rowslow",      -- pulling ahead, gently
    left   = "rowingl",      -- port oar
    right  = "rowingr",      -- starboard oar
},
```

`boats_db.VESSELS.rowboat.pose` moves from `sit` to `rowing`. The rowboat is the
only oared hull here: a longboat's pilot stands at the guide slot, which is the
**helmsman's** station per Immersive Travel's mount data, so its oarsmen are not
the player and it stays `stand`.

### Turning outranks throttle, which already suited rowing

`vesselField` already resolved turning before throttle, for the gondola. On an
oared boat that is not a compromise but the actual technique — you turn by
pulling one oar — so holding ahead-and-starboard correctly plays `rowingr`
rather than the ahead stroke. No change needed.

### No backing stroke, deliberately

The clip has none. The nearest candidate would be playing a forward stroke
while the hull slides astern, which is the same mismatch as a creature playing
`walkforward` while moving backwards — something this project has twice treated
as a bug, once in the mount controller and once in the gait notes. So astern
falls through to `base`: oars shipped, drifting backwards, which is how a
rowboat usually goes backwards anyway.

### `slow` is what became of `paced = true`

The stub reserved `paced = true` — "stroke rate follows boat speed" — as a
playback-rate idea. The clip answers it differently, with a second and gentler
stroke, so it became a stance field fed by a speed **band** rather than a
`speed` multiplier. Coarser than scaling, but it is the animator's own timing in
both strokes, which scaling is not.

The band is the one thing the pose takes from the **hull** rather than the
pilot's hands: the oars are what made the boat fast, so the stroke should match
how the boat is actually moving, not which key is held.

Two thresholds, not one:

```lua
poseFastAbove = 0.55,   -- below the band, rise above this to drive
poseSlowBelow = 0.35,   -- above the band, fall below this to ease off
```

The band is crossed on every departure and every stop, and a single threshold
would swap the stroke back and forth while the hull sat near it. The gap is
deliberately wide: being in the "wrong" stroke for a moment costs nothing,
flicker is visible.

### Compatibility in both directions

`vesselField(stance, turn, throttle, fast)` takes `fast` as a fourth argument
where `nil` means fast, and `onAnimVesselHelm` treats an absent `data.fast` the
same way. So a Boats build predating the band drives rather than silently easing
off, and the gondola, stand and sit stances are untouched because they have no
`slow` field.

### Two existing tests were changed, and why

`test_boats_scripts.lua` asserted *"rudder pose sent once, on the change"* and
started reporting 2. The cause was in the test, not the code: its turning loop
never advanced the pilot's position, so nine frames in, the bumper correctly
concluded the boat was wedged and took its way off — and the new band correctly
reported the drop to the gentle stroke. A turning boat makes way, so the loop now
advances the pilot the same way the straight-ahead loop above it always did. The
assertion is unchanged.

`test_ridinganim.lua` asserted *"an unregistered stance (rowing, future) falls
back to stand"*. It ships now, so that assertion is split: an unknown stance
(`coracle`) still falls back to `idle`, and `rowing` is asserted **not** to.

### New assertions worth knowing about

- `rowingidle` has no loop keys at all, so the key-candidate list must fall
  through to `start`/`stop`. Tested, against the real clip's times.
- `rowingl` plays — the renamed group, so the rename is covered by a test and
  not just by the asset.
- Astern ships the oars rather than rowing forwards.
- A helm event with no `fast` field drives rather than easing off.
- From rest, full ahead reports gentle **then** driving, crossing the band
  exactly once; holding at speed produces no further band traffic; coasting to a
  stop crosses once on the way down.

Not verified in game. Worth checking: that the rowboat rows at all, that
`rowingl` and `rowingr` are not mirrored (§1), and that the band changes stroke
somewhere sensible rather than right off the jetty.
