# 2026-10-09 — gondola poses in ridingAnim

## 1. xGondola1*.kf: the loop keys named the wrong group

All six copies (xbase_anim, _female, kna and their .1st) shipped as:

```
0.000  godola1: start
0.500  godola1: loop start
4.167  godola1: loop stop
4.333  gondola1: stop
```

OpenMW groups text keys by the text before the colon, so this declares two
broken groups: `godola1` (no stop) and `gondola1` (only a stop). Neither can
play its loop. `gondolar` / `gondolal` were correct.

Fixed in place with the new `tools/fix_textkeys.py godola1 gondola1`, which
rewrites only NiTextKeyExtraData strings and refuses to write if the block
count or structure changes (NIF 4.0.0.2 stores no offsets, so the 3-byte
growth is safe). Fix the source .blend/.kf export too, or the next export
brings it back.

## 2. check_anims.py passed the broken clip

It counted a group as declared if ANY key named it, so `gondola1: stop` alone
made `gondola1` "present on ALL skeletons". It now requires `start` and
`stop`, and `loop start`/`loop stop` as a pair, and lists incomplete groups
as failures. Run against the shipped clip it reports both halves of the split.

## 3. ridingAnim.lua: vessel poses

New VESSEL POSE section, driven by WhyWalk Boats:

| Event | Data | Effect |
|---|---|---|
| `WhyWalk_AnimVesselStart` | `stance` | pose after the boarding teleport lands |
| `WhyWalk_AnimVesselHelm` | `turn`, `throttle` (signs) | swap loop; sent on change only |
| `WhyWalk_AnimVesselStop` | — | release |

Data in `whywalk_shared.lua` (VESSEL_GROUP, VESSEL_KEY_CANDIDATES,
VESSEL_STANCE validated at load, VESSEL_TUNING, buildVesselLayer), in the
same shape as Take a Seat's and ErnGlider's `_shared` files:

- `gondola`: base `gondola1`, left `gondolal`, right `gondolar`, each looping
  `loop start` → `loop stop` (first key pair the clip has, via
  `animation.getTextKeyTime`).
- `stand`: `idle`. `sit`: `vasittingfloor` if a pack provides it, else `idle`.
- FUTURE: ROWING — reserved, commented shape (`base/stroke/back/left/right`,
  `paced`). The controller already selects `stroke`/`back` from the helm
  throttle when a stance has them; nothing ships until a .kf defines the
  groups. Unknown stances fall back to `stand`.

Layer: whole body at `PRIORITY.Hit` (above Movement, below Weapon / Block /
Knockdown / Torch). A helm change inside `minPoseTime` (0.3 s) is deferred by
a generation-guarded one-shot timer, so the pose always ends on the latest
helm state. AnimRefresh re-poses after a perspective switch; the ended
handler re-issues under the existing burst guard. Mounting clears a vessel
pose; the camera offset is not applied aboard.

## 4. Also fixed in ridingAnim.lua

- **`loops = -1` in playLoop.** Cod3x: `loops` is a number >= 0; -1 is out of
  range (the same constant the controls-port note found in the mount script).
  Now `LOOPS = 999999`. Rider poses were relying on `forceLoop` alone.
- **onSave / onLoad.** A looping pose survives a save while the script's
  memory of it does not (build review §3). Rider and vessel group names are
  saved and cancelled on load.

## 5. tools/test_ridinganim.lua could not run

It read a `SCRIPT_PATH` global no runner set (`attempt to index a nil value
(local 'mod')`). It now defaults the path. 10 existing + 21 new vessel
assertions pass, against the REAL vessel stance table and the fixed clip's
key times.

## 6. Boats module

`boats_pose.lua` is retired (and removed from WhyWalk_Boats.omwscripts);
`boats_player.lua` sends the three events above. `boats_db` vessel `pose`
fields are now Core stance names: gondola and ornate gondola `gondola`,
rowboat `sit`, the rest `stand`. Its tests check every pose is a Core stance.
