# WhyWalk — 2026-10-08 build review

Checks, bugs, comment audit, AnimRefresh v5 usage, and a functional comparison
against p37z.

Headline: **six defects, two of them severe.** Both severe ones share a shape —
code that *looked* correct and could never run. One was a diagnostic that could
not print; the other was a jump that could not land.

| | finding | severity |
|---|---|---|
| 1 | jump in an interior never lands — mount falls forever | **severe** |
| 2 | `reissueTotal` declared below first use → the flicker diagnostic could never fire | **severe** |
| 3 | mount script `onLoad` dropped the group *name*, not the animation | moderate |
| 4 | `onLoad` could return before deciding attach/detach | moderate |
| 5 | dead perspective relay held an AnimRefresh subscriber open per ride | minor |
| 6 | AnimRefresh version guard raises on a copy with no `version` | latent |

All six fixed. Plus the comment audit, two tool bugs, and one architectural gap
that is **not** fixed and should drive the next pass.

## 1. Jump in an interior never lands  *(severe, new)*

`session.airborne` is cleared in exactly one place — the landing clamp in
`stepMovement`:

```lua
local gz = groundZ(pos, s.mount.cell)
if gz and pos.z <= gz then
    pos = util.vector3(pos.x, pos.y, gz)
    if s.airborne then s.airborne, s.vz = false, 0 end
end
```

and `groundZ` refuses every interior by design:

```lua
if not (cell and cell.isExterior) then return nil end
```

So indoors `gz` is always `nil`, the clamp never fires, and nothing ever clears
`airborne`. `vz` winds down to `-maxFall` and the mount sinks through the world
indefinitely with `riderState` pinned to `STATE.JUMP` — the rider stuck on the
jump animation, the mount stuck on its jump gait. Measured in simulation:
**-78,043 units after 83 seconds.** Nothing recovers it short of dismounting.

The interior gate is not the bug; it is correct, and Cod3x documents
`getHeightAt`'s cell argument as one "in their exterior world space". The bug is
that the only exit from the airborne state was placed behind it.

### The fix, and why it needs no raycast

A downward probe is the obvious answer and is **not available here.** Confirmed
in `ref/cod3x/omw_context_plugin.lua`:

```
127:  ['openmw.nearby'] = ACTOR_CONTEXT,
```

`openmw.nearby` is local-context only, so `whywalk_global.lua` — a GLOBAL
script — physically cannot raycast. That is also the real reason `groundZ` reads
a heightmap rather than casting a ray, and it is worth recording as the
constraint it is rather than rediscovering it next time.

The arc supplies the answer instead. It is symmetric, so **a jump returns to the
height it left from.** Capture that height at takeoff and use it as the floor
when the heightmap has none:

```lua
-- at the jump
session.jumpFromZ = session.mount.position.z

-- in the clamp
if not gz and s.airborne then gz = s.jumpFromZ end
```

Two details:

- **Only while airborne.** A floor applied the rest of the time would pin the
  mount to the height of its last jump for the remainder of the interior.
- **This is not a weaker assumption than the exterior path.** That path reads a
  heightmap and ignores collision entirely (see §7). Both assume flat ground
  under the mount; indoors, "flat at takeoff height" is at least exactly right
  at the moment of takeoff.

Verified in `tools/test_jumparc.lua` — **42 checks, 0 failures.** Across frame
times 1/144, 1/60, 1/30 and 0.1 and takeoff heights 0, -1200.5 and 4096: lands
every time, lands at takeoff height to 1e-9, and the arc stays within one frame
of the continuous solution (2·480/900 = 16/15 s). The exterior path is unchanged
at both assertions.

The test also greps `whywalk_global.lua` for the three lines of the fix and fails
if any has gone — run against the pre-fix source it reports 3 failures by name.
`stepMovement` is a local in a global-context script and cannot be required, so
the arc itself is a replica; the grep is what ties the replica to the original.

## 2. The flicker diagnostic could never fire  *(severe)*

`local reissueTotal, rideStartedAt = 0, 0` sat at line 521, next to the handler
that increments it — but `onAnimMounted` (line 429) and `onAnimDismounted`
(451-461) are defined *above* that point. In Lua those earlier uses bind to
**globals** of the same name. The ended-handler incremented the local;
`onAnimMounted` zeroed the global; the dismount report read the global. The
condition was permanently `0 > 0`.

Which means **the instrumentation added on 2026-10-04 to measure symptom 3 was
dead on arrival.** The line asked for was never going to print, whatever the
re-issue rate.

Fixed by moving the declaration above first use. Worth noting what caught it:
nothing in the toolchain. `luacheck` accepts it, `globalcheck` reports undeclared
*reads* only, and no checker models declaration **order** (§6). The only defence
is the habit.

`tools/test_ridinganim.lua` gained TEST 5, which captures `print` and asserts the
report fires with the right count. Against the unfixed build it fails
(`[printed: 0 line(s)]`); against the fix, 10/10.

## 3. Mount `onLoad` dropped the reference, not the animation

`whywalk_mount.lua`'s `onLoad` cleared `currentGroup` to `nil`. But a looping
animation **survives a save/load** — so the group kept playing while the script
forgot its name, leaving `stop()` with nothing to cancel. Symptom: a guar walking
on the spot forever, with no way to stop it.

Added `onSave` to persist the held group name, and `onLoad` now cancels it before
clearing:

```lua
local function onLoad(data)
    local held = data and data.group
    if held then animation.cancel(self, held) end
    currentState, currentGroup = nil, nil
end
```

Also removed from that file: an unused `openmw.types` require, and the dead
`GAIT` table (declared, never read — the `FALLBACK` chains carry the real names).

## 4. `onLoad` could return before deciding attach/detach

In `whywalk_global.lua` the early returns for "not resuming a ride" ran *before*
the mount-script detach, so a save made mid-ride could leave `whywalk_mount.lua`
attached to a creature nobody is riding — and attached scripts **persist in the
save**, so it stays there. Restructured so the decision precedes every early
return.

## 5. Dead perspective relay

`whywalk_player.lua` carried `EV.PERSPECTIVE`, `lastFirstPerson`,
`sendPerspective`, `subscribePerspective`/`unsubscribePerspective`, the
`openmw.camera` require and a `"WhyWalkPerspective"` AnimRefresh subscription.
Its only consumer — `placeRider`'s first-person gate — was removed on 2026-10-04
when yaw became a delta.

Not free: it held an AnimRefresh subscriber open for every ride and ran a
camera-boundary comparison per frame to feed nothing. Removed, with a comment
recording what it was and why it went. Matching removals in
`whywalk_global.lua` (`EV.PERSPECTIVE`, `session.firstPerson`, `onPerspective`).

## 6. AnimRefresh version guard raises on a version-less copy  *(latent)*

```lua
if I.AnimRefresh and I.AnimRefresh.version >= MY_VERSION then
```

Interface names are one global namespace, and this guard runs against whatever
already holds `"AnimRefresh"` — which need not be this file. A copy predating
versioning, or an unrelated mod using the name, exposes no `version`, and
`nil >= 5` does not evaluate to false: it raises *attempt to compare nil with
number* and takes v5 down with it. The service would then be missing, silently,
for every subscriber.

Checked: **v3 (shipped in Take a Seat) and v4 both expose `version`**, so no
known copy triggers this. Hardened anyway to `(I.AnimRefresh.version or 0)`,
because the cost is nothing and "no version field" has one unambiguous meaning —
older than the field.

This is not the pcall anti-pattern. Nothing is swallowed; the guard reaches the
same decision it would with the field present.

## AnimRefresh v5 usage — clean

| | |
|---|---|
| registered | `PLAYER: scripts/AnimRefresh/AnimRefresh_v5.lua` |
| subscribers in this mod | **one** — `ridingAnim.lua`, key `"WhyWalk"` |
| lifecycle | `subscribe` on mount, `unsubscribe` on dismount |
| idle cost when not riding | zero subscribers, so no delivery work |
| stale copies | none; `AnimRefresh_v3.lua` removed on 2026-10-04 |
| `UiModeChanged` | under `eventHandlers`, verified by `check_handlers.py` |

The second subscription (`"WhyWalkPerspective"`) is gone with §5, so the one
remaining subscriber is the one that does something. `ridingAnim.lua` returns
`false` from its callback when the model is not ready, which is the v4+ retry
contract, and does not set `verify` — correct, since it attaches no VFX.

Path capitalization is consistent with Take a Seat's copy
(`scripts/AnimRefresh/AnimRefresh_v*.lua`). The lowercase spellings elsewhere in
the build are prose quoting the engine's own log line, not path references.

**Still outstanding from 2026-10-04, outside this build:** the `UiModeChanged`
fix needs porting to **CAKE, IED, Take a Seat and Bardcraft**, which ship the
same file at the same shared path. v5's `>=` guard makes the fixed copy win
wherever it is installed, so WhyWalk alone is enough to repair the *behaviour* —
but each of those mods keeps logging `Not supported handler 'UiModeChanged'`
until its own copy is replaced.

### One file was not code at all — fixed

`whywalk_siltstrider.lua`: 165 lines, of which a 160-line block comment and
`return { }`. Commented out of the manifest, required by nothing, loaded by
nothing. A research catalogue wearing a `.lua` extension — in the script tree,
the checker surface and the VFS, for no runtime benefit.

Moved to **`SILTSTRIDER_NOTES.md`**, content intact. References updated in
`WhyWalk_README.md`, `whywalk_shared.lua` and the manifest comment. That alone
takes the tree from 46% to **41%** comment and from 8 scripts to 7.

### The rest is mostly earned, with one real excess

The large headers are not padding. `whywalk_mount.lua`'s 45 lines explain why a
teleport produces a T-pose, which is the single least guessable fact in the
build; `whywalk_global.lua`'s `groundZ` comment records the local-context
constraint that §1 had to rediscover. Comments that say *why not* are the ones
worth their length, and this codebase has mostly those.

The excess is **duplication between code comments and shipped docs**:

- `AnimRefresh_v5.lua`'s 131-line header largely restates `ANIMREFRESH_V5.md`
  (97 lines). Both describe the v4→v5 rationale and the shared-path problem.
- `whywalk_global.lua`'s header overlaps `WhyWalk_README.md`'s architecture
  section.
- `RESEARCH.md` alone is 2,034 lines — 65% of all shipped prose.

Recommendation, not applied: let the header state the contract and the
non-obvious constraints, and point to the `.md` for history. The v5 header's
account of *why the filename carries the version* belongs in the file (someone
editing it needs it); its account of *what changed in v4* belongs in the doc.
That would cut roughly 60 lines without losing anything.

Nothing in the audit suggests stripping the *reasoning* comments. Items §1 and
§2 were both invisible to every automated check in the toolchain; prose is what
is actually carrying that knowledge.

## Against p37z

Both mods mount a creature and ride it. They disagree on the one decision that
matters, and p37z is on the right side of it.

| | WhyWalk | p37z |
|---|---|---|
| mount driven by | `teleport` every frame, GLOBAL | `controls.movement` / `sideMovement` / `run`, LOCAL on the creature |
| gait animation | separate CUSTOM script, event-driven | engine, from the controls it was given |
| collision | **none** | engine |
| gravity / jump | hand-integrated Euler arc | engine |
| ground | `core.land.getHeightAt`, exteriors only | engine |
| pathing / navmesh | none | `nearby.findRandomPointAroundCircle`, `NAVIGATOR_FLAGS.Walk` for the dismount spot |
| saddle offset | per-type `PROFILE` table, 8 types | `getBoundingBox()` + one `Offset` |
| mount trigger | activation via player script | `onActivated` on the creature |
| combat safety | none | refuses to mount an actor in combat with the player (`I.AI.getTargets('Combat')`) |
| rider yaw | delta, applied on top of mouse-look | absolute, with a broken sentinel (below) |
| per-frame handlers | one `onUpdate` while riding | `onUpdate` + an update-function registry |
| external deps | none | `I.s3.lf`, unbundled |
| l10n | yes | no |
| mount types | 8, pattern-matched | whatever is activated |

### What p37z gets for free that WhyWalk reimplements

p37z writes intent and lets the engine resolve it:

```lua
s3lf.controls.run = inputInfo.run ~= inputInfo.alwaysRun
s3lf.controls.sideMovement = value
s3lf.controls.yawChange = s3lf.controls.yawChange + inputInfo.yawChange
```

From those three the engine supplies gait selection, root motion, collision,
gravity, slope handling, step-up, water, and navmesh awareness. WhyWalk
hand-writes the fourth of that list it has (gait via `whywalk_mount.lua`, an Euler
arc, a heightmap clamp) and **does without the rest** — which is exactly how §1
came to exist. A teleport-driven mount has to re-derive everything the character
controller already does, and each piece is a place for a bug like §1 to live.

The LOCAL-vs-GLOBAL choice is upstream of all of it. p37z runs on the creature,
so it has `nearby` and `controls`; WhyWalk runs globally, so it has neither.

### What WhyWalk does better

- **Rider yaw.** WhyWalk applies the *change* in mount heading, so mouse-look
  survives. p37z writes an absolute angle with zero as its "no request"
  sentinel — and zero is also due north:
  ```lua
  local targetYaw = 0.
  if not firstOrThird then
      if util.round(math.deg(myYaw)) ~= util.round(math.deg(MountTarget.rotation:getYaw())) then
          targetYaw = myYaw
      end
  end
  ```
  When the two headings round equal, `targetYaw` stays 0 and the rider is snapped
  to face north. An absolute angle cannot distinguish "facing north" from "no
  request"; a delta can, because zero genuinely means "no change".
- **Dead dedupe guard**, still present at `creatureMount.lua:36`:
  ```lua
  for i = numUpdaters, -1 do if self.queue[i] == updateFunction then return false end end
  ```
  Default step is `+1` and `numUpdaters >= 0`, so the body never executes. The
  same update function can be registered twice and will then run twice per frame.
- **No external dependency.** `I.s3.lf` is required but not bundled.
- Per-type tuning, localization, and a documented MWScript bridge with a
  fail-safe rename.

### Recommendation

Port the movement model, not the mod. Move steering into a local script on the
creature and write `controls.movement`/`sideMovement`/`yawChange` instead of
teleporting. That deletes `stepMovement`, `groundZ`, the jump arc, §1, and the
collision gap below in one change, and it keeps everything WhyWalk does better —
the yaw delta, the profile table, the l10n. It is a large change and should be
its own pass.

## 7. Not fixed: there is no collision at all

Flagged because it outranks everything above and is not a bug so much as a
missing subsystem.

WhyWalk's only world query is `core.land.getHeightAt` — a heightmap lookup. The
mount therefore **phases through walls, rocks, trees, buildings and actors**, and
on a bridge or any placed mesh it sinks to the terrain height underneath.

Devilish Guar Riding — the mod you said feels best — had the full set, and none
of it survived into WhyWalk:

```
OBSTACLE_RAY_HEIGHTS   MAX_STEP_UP / MAX_STEP_DOWN
GROUND_PROBE_UP/DOWN   CEILING_PADDING
```

That is a regression against the reference implementation, and it cannot be
repaired in `whywalk_global.lua`: all of it needs `nearby`, which is
local-context only (§1). Two routes:

1. **Probe from the mount script.** `whywalk_mount.lua` is already LOCAL on the
   creature, so it can raycast. It would report ground and obstacles back to the
   global script by event. Keeps the architecture, adds per-frame rays and a
   frame of latency.
2. **Port the movement model** (above). Collision stops being WhyWalk's problem.

Route 2 is the better answer and route 1 is the smaller one. Either way the
interior floor from §1 stays — it is the correct fallback when no probe reports
ground.

## 8. Two tool bugs

Both found while running the suite, and both mean a check has been reporting
clean without testing anything.

**`check_names.py`'s unused-require check is vacuous.** It counts references in
`body`, which is the *whole* source including the require line, then flags
`hits <= 1`. Any require referenced even once elsewhere scores 2+; one referenced
nowhere scores exactly 1 and is correctly flagged — but the comment stripper runs
first, so a require used only inside a comment also scores 1. The real problem is
narrower than it looks, but the check has never fired on this codebase despite
`whywalk_mount.lua` carrying an unused `openmw.types` require (§3), which I found
by reading. Worth a test.

**No checker models declaration order.** §2 is the proof. `luacheck` parses
fine, `globalcheck` reports undeclared *reads* only, and a local used above its
`local` statement silently becomes a global read *and* a global write — so even
`globalcheck`'s read check misses it, because the name genuinely is read as a
global and that is reported as... nothing, since the write makes it exist.

A pass that flags "name assigned at line N is declared `local` at line M > N" is
the single highest-value addition to the toolchain. It catches a class of bug
that produces no error, no warning, and code that reads correctly.
