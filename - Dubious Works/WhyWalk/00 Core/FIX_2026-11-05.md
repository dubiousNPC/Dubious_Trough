# Core and Boats: test pass, rider-pin liveness fix (2026-11-05)

## Results

| | Lua 5.4 tools | real LuaJIT 2.1 | OpenMW 0.52 |
|---|---|---|---|
| Core | resolveanim 67, saddlebox 51, mountcontrols 34, ridinganim pass; static checks clean | all pass | loads clean; `test_wwapi` 12/12 |
| Boats | 213 + 64, 43 traced data values, static checks clean | all pass | loads clean |

`check_luajit` (from Caravans) finds no LuaJIT incompatibilities in any WhyWalk script.

## Fixed

1. **The rider-pin liveness check declared a working pin dead.** `SetPos` does not clear the
   player's falling speed, so a rider who isn't levitating (a caravan passenger) falls
   between pins. In OpenMW 0.52, with the pin running and a target moving at 1400 u/s,
   tracking was horizontally exact (0.0 every frame) and up to 146–198 below the target
   vertically. The check used 3D distance, so that fall made 20 straight "misses".
   Through `I.WhyWalkRiderPin` the original Core printed
   "The MWScript rider pin is not running … recompile WhyWalkRiderPin" after about 500
   frames, which is the 2026-11-03 report.

   The check now uses horizontal distance. In the same run, the fixed Core keeps the pin.

2. **That message's advice was wrong.** OpenMW compiles MWScript from source
   (`ScriptManager::compile` reads `mScriptText`; Morrowind bytecode is never used), and
   the shipped `WhyWalk.esp` carries bytecode anyway. The message now points at the load
   order and at other mods moving the player. The comment block is corrected to match.

3. **`check_anims` had been checking nothing.** `check_all.sh` passed it `scripts/*.lua`,
   but it reads `animations/` under its first argument. It reported every folder ABSENT
   and passed on 0 groups. It now runs on `.` and checks 18 groups × 4 skeletons, all
   present.

4. **`test_wwapi` (the engine suite):** fixed three bugs in the probes themselves.
   - The two teleport probes removed their object in the same frame as the teleport, and
     the engine refuses that ("Can't remove 0 of 0 items").
   - A player-context probe required `openmw.world`.

   Every API assumption is now confirmed in OpenMW 0.52: the `meshes/` prefix, double
   teleport raising, enums raising on unknown keys, `I.UI.MODE` being userdata, the yaw
   convention, the silent no-op on missing groups, and `loops = -1` being out of contract.

5. **Caravans' LuaJIT test shim** rebuilt `math.atan2` from the host `math.atan`, which
   breaks on real LuaJIT. It now only fills in what a 5.3+ host lacks.

## Not covered

- `xbase_anim_female.1st` and `xbase_animkna.1st` are present but not in `check_anims`'
  default skeleton list.
- Boats was loaded in the engine but not sailed: the test game has no boat mesh or water
  route.
- A non-levitating pinned rider still sinks between pins until collision catches them.
  Caravans' cabin floor does that at slot z 1226. Applying Levitate during a journey, as
  mounts do, would remove the sink entirely.
