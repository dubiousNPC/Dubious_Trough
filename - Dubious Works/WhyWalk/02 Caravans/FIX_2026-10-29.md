# Caravans — the four ride faults (2026-10-29)

All four were in the same handful of lines, and three of them were the same
mistake: placement code that derived a value a second time instead of using
the one already computed.

---

## 1. The strider stood at the player's height

`placeVehicle` was handed the route point. The occupants were handed
`z - bodyOffset`. Two call sites, same quantity, derived separately — so they
disagreed by the whole `bodyOffset`, 1220 units, and the strider's feet ended
up at the rider's waist with everything hovering.

The route is authored through the rider's body, not the strider's feet, which
is what `bodyOffset` records. Both now come from one function:

```lua
local function bodyOrigin(s, z)
    return z - (s.vehicleDef.bodyOffset or 0)
end
```

`placeVehicle`, both occupants and the dismount all take that origin. Slot
z 1223 against bodyOffset 1220 is why a rider sits 3 units above the route
point — which is exactly the gap the old code left between the player and the
strider's feet, and the number the test prints when the fix is reverted.

## 2. No animation on the player

Nothing was ever asked for. Caravans placed the player and never posed them.

It now uses **Core's vessel-pose layer** rather than a new one.
`ridingAnim.lua` is already on the player, already owns the blend layer and
the group fallback, and already re-asserts a pose the engine interrupts —
which matters more here than on a boat, because a passenger teleported along a
route counts as **airborne** every frame and the engine's falling animation
outranks a pose that is not re-played. A hand-rolled version would have had to
rediscover that.

Two events per journey, none per frame:

```lua
self.object:sendEvent('WhyWalk_AnimVesselStart', { stance = 'passenger' })
self.object:sendEvent('WhyWalk_AnimVesselStop', {})
```

The new `passenger` stance in `whywalk_shared.lua`:

```lua
passenger = {
    base = { "rasit2", "vasittingfloor", "idle" },
},
```

A **list**, because xRAsit1 is not a dependency. `resolveVesselGroup` filters
on `animation.hasGroup` before choosing, which is load-bearing rather than
defensive: `playBlended` on a group the skeleton lacks is a silent no-op, so an
unguarded `rasit2` would leave the player standing with no animation and no
error in the log.

I read the pack rather than taking the group name on trust —
`xdbsRAsitting1.kf` declares `rasit1`–`rasit8`, `rasitup1` and
`rasitf`/`f1`/`f2`, in all six skeleton folders. `rasit2` is there, with
`start`/`stop` keys and no loop keys, so the pose uses the start/stop pair.

The STOP is sent on arrival, on **every** abort, and on load. An abort that
left it running would leave you sitting cross-legged in mid-stride for the
rest of the save.

## 3. The camera was welded to the strider

```lua
obj:teleport(cell, pos, util.transform.rotateZ(YAW_SIGN * yaw))   -- every frame
```

In third person the body yaw and the camera yaw are the same number, so
rewriting the body every frame overwrites whatever the mouse just did.

This is solved in Core already, for the rider pin, and the fix carries over
unchanged — the yaw goes over as a **change**, not a heading:

```lua
playerYaw = playerYaw + (heading - headingLastFrame)
```

The body still turns with the strider, so you do not end up sideways through a
corner, and your own look offset survives because it is already in `playerYaw`
when the delta lands on top of it. Zero is a safe "do nothing" for a delta, so
the rotation argument is **omitted** on a frame with no turn —
`TeleportOptions.rotation`: *"if missing, then the current rotation is used."*

The guide keeps the absolute heading. They have no camera, and facing forward
is the whole point of them.

## 4. The driver rode behind you

Immersive Travel's own data puts the player at `y = 80` and the caravaner at
`y = 10`, so the passenger sits in front and the driver rides at your back.
The two y values now trade places. Only y: x and z are still [R]'s, and the
two spare passenger seats are untouched, so the bench still reads as one.

The `-- src:` comments now record the deviation rather than quietly claiming
the numbers are imported.

## Tests

The last round's lesson was that the interception shipped with nothing
covering it. So each of these four has an assertion that **fails if the fix is
reverted**, and I checked that rather than assuming it:

| revert | what fails |
|---|---|
| vehicle back to the route point | `player z - vehicle z = 3.0, slot z = 1223` — the reported symptom, as a number |
| player back to an absolute yaw | `player 1.2374 vs strider 1.2374` — the camera lock, as a number |
| pose events removed | START, stance, STOP, abort and load — 5 assertions |
| slot y values back to [R]'s | `guide y=10 player y=80`, and the world-space check |

`test_intercept.lua` now drives the **real global script** through a real
Balmora → Ald-ruhn journey against the shipped route data, recording every
teleport instead of performing one: where the three bodies land, whether a
rotation was written at all, and what the player's yaw is after 400 frames of
cornering with 1 radian of mouse-look applied. That last one is the camera
assertion — the player's yaw must come out at `1.0 + (heading change)`, not at
the heading.

`test_ridinganim.lua` covers the stance from both sides: with `rasit2` absent
from the skeleton it must fall through to idle, and with it present it must
play `rasit2`, loop, and use the blend layer.

Totals: `test_intercept` 57, `test_caravans` 81, `test_ridinganim`,
`test_resolveanim` 67, `test_mountcontrols` 34, `test_saddlebox` 26,
`test_boats` 213, `test_boats_scripts` 62 — all passing. check_load,
check_handlers, check_names, globalcheck, check_declorder, ctxcheck,
api_sweep, check_manifest and luacheck clean on all three modules.

### A stale checker, found on the way

`ctxcheck.py` reported `textSet.lua  NO-ANNOTATION`. The file has
`---@omw-context menu` on line 2 — Boats was shipping an **older ctxcheck**
that only reads line 1, and line 1 of that file is a `---@diagnostic`
directive. Core had the fixed version. Boats' copy is now synced and Caravans,
which shipped none, has one. The other seven duplicated tools were checked and
are byte-identical across modules.

Worth knowing because it cuts the other way too: that checker was reporting
nothing on any Boats file whose annotation is not on line 1.

## What to look for

1. **The strider should stand on the ground**, with you and the caravaner up on
   its back rather than level with its feet.
2. **The caravaner should be in front of you**, facing forward.
3. **You should be able to look around freely** while the strider turns under
   you, and your body should still swing with it rather than staying put.
4. **You should be sitting.** If xRAsit1 is installed you get `rasit2`;
   without it you will be standing on the bench, which is the fallback working
   rather than a fault. If you expect `rasit2` and get a stand, the pack's
   `.kf` files are not reaching `meshes/xbase_anim/` and friends.
