# Caravans — the travel menu never appeared (fix, 2026-10-28)

Your log, on opening a caravaner's travel topic:

```
[WhyWalk Caravans] I.UI.MODE has no Travel entry ...
[WhyWalk Caravans]   I.UI.MODE   = (not a table)
[WhyWalk Caravans]   I.UI.WINDOW = (not a table)
```

`I.UI.MODE` does have `Travel`. The script never looked.

## Blocker 1 — a `type()` check on a userdata proxy

```lua
local M = I.UI and I.UI.MODE
if type(M) ~= 'table' then return nil end   -- always true in the engine
return M.Travel
```

`I.UI.MODE` (and `I.UI.WINDOW`) are read-only **userdata** proxies, not tables.
`type()` never returns `'table'` for them and `pairs()` cannot list them. So the
module stood down on every travel menu, and the diagnostic that was meant to
list the names printed "(not a table)" instead.

**Fix:** `local TRAVEL_MODE = I.UI.MODE.Travel`, indexed directly at load. If a
build ever lacks it, that line errors loudly instead of standing down in
silence. The `pairs()` diagnostic is gone.

**Correction to `FIX_2026-10-23.md`.** That note concluded "`I.UI.WINDOW` has no
`Travel` entry". The evidence for that came from the same kind of check on the
same kind of proxy, so the conclusion is unproven. The mode-based interception
it led to is still the right mechanism (Ben's Rideable Silt Striders works off
`I.UI.MODE.Travel`), but treat the WINDOW claim as unverified.

## Blocker 2 — destinations matched by name, but `cellId` is not a name

With blocker 1 fixed, the menu would still have had zero rows. Each
destination's `cellId` was lower-cased and looked up as a route key
(`"balmora"`), but an exterior destination's `cellId` is an engine id, not a
place name. Nothing would ever have matched, and the vanilla window would have
stayed up.

**Fix:** places are now matched by **position** (`caravans_stops.lua`, new):

- Each stop's centre is the median of every route endpoint that names it.
- The global script resolves the guide's position to the origin stop, and each
  destination's position to a destination stop, within 15000 units. On the
  shipped data the closest two stops (Suran and Vivec) are ~30300 apart, and the
  furthest good endpoint is ~13300 from its stop, so no position can match two.
- The quote comes back indexed like the record's `travelDestinations`, and it
  names the guide it is for. A late reply for a different guide is ignored.

## A data fault found on the way

`suran -> balmora` from Immersive Travel ends ~47500 units from Balmora (the
other six Balmora endpoints agree to within ~1500). Taking it would have put
you down in the wrong place. Routes whose ends are not at their named stops are
now dropped at load and the reverse direction is used instead (here,
`balmora -> suran`, walked backwards). The log reports it every load:

```
[WhyWalk Caravans] route dropped, reverse used instead: suran -> balmora (ends 47535 from balmora)
```

## It no longer stands down in silence

Whenever the vanilla window is kept, the log says why, once per reason per
session:

```
[WhyWalk Caravans] vanilla travel window kept: UI Toolkit is not installed
[WhyWalk Caravans] vanilla travel window kept: no route quote for this guide yet
[WhyWalk Caravans] vanilla travel window kept: guide is not at a known stop
[WhyWalk Caravans] vanilla travel window kept: <guide> offers N destinations, none with a route from <stop>
```

The global script also prints once per guide when it can animate none of that
guide's destinations.

## Why the tests passed last time

`tools/test_intercept.lua` modelled the engine wrong in exactly the two places
that broke:

- `I.UI.MODE` was a plain table. It is now a non-table proxy that raises on
  unknown keys and on `pairs()`.
- Destinations had `cellId = 'Ald-ruhn'`. They now have opaque ids, and the
  quote is produced by the **real** global handler against the **real** route
  data instead of being written by hand.

Putting the old `type()` gate back into the player script makes six assertions
fail. Results: `test_intercept` 36/36, `test_caravans` 78/78. check_load,
check_handlers, globalcheck, check_manifest, ctxcheck, check_declorder and
luacheck are all clean.

## What to look for in your next log

- At load: the `route dropped` line above. That one is expected.
- Talking to a Balmora caravaner and choosing Travel should give the UI Toolkit
  destination list. If it doesn't, there will be a `vanilla travel window kept:`
  line with the reason.
- One timing case: the route quote is requested when you activate the guide and
  arrives a couple of frames later. Clicking Travel faster than that keeps the
  vanilla window for that one open, and logs "no route quote for this guide yet".
