# Caravans — the 340-degree turn (2026-10-31)

Your description named the bug precisely enough to find it: **"a 20 degree
right turn is performed as 340 degree left turn"** is the long way round, and
that is exactly what was happening.

---

## 1. The heading was normalised, and that was the fault

`easeHeading` ended with `% TWO_PI`, which kept the heading tidily in
[0, 2π). The arithmetic was never wrong — `angleDiff` takes the short arc and
the step is clamped, so the heading only ever moves 1.34 degrees per frame.
I verified both and they hold across the wrap.

What was wrong was the **value handed to the engine**, which jumped a full
turn every time the strider's heading crossed north:

```
frame n      6.2797 rad     (359.8 degrees)
frame n+1    0.0036 rad     (  0.2 degrees)
```

0.4 degrees of actual turn, delivered as a −359.6 degree change. Anything
downstream treating consecutive rotations as a continuous quantity takes the
long way — extreme turns, in the wrong direction, with the body drifting back
afterwards. Every turn that crossed north did this; turns that did not were
fine, which is why it read as intermittent.

The fix is to stop normalising. Nothing needs it: `angleDiff` wraps
internally and `rotateZ` is periodic, so `rotateZ(6.2833)` and `rotateZ(0)`
are the same rotation. The value grows by at most a few turns over a journey,
which no float cares about.

### My symmetry test missed it, and I can say why

Last round I tested the easing for handedness and reported it symmetric. That
was true and useless: my spiral path had a continuously increasing heading
that **never crossed the wrap boundary**. The test exercised the arithmetic
and never the discontinuity, so it passed on a build that spun the strider
nearly all the way round once a corner.

Worse, an existing assertion made the bug a *requirement*:

```lua
check('continuing to ease wraps across north rather than going the long way',
      crossing > math.pi, crossing)          -- asserts the NORMALISED value
```

That test helped the fault survive two rounds by insisting on the thing that
caused it. It now compares angles rather than numbers, and there is a
continuity assertion alongside it:

```
FAIL turning one way, no single step jumps anything like a full turn
       -> worst raw step 6.2499 rad
```

That is your 358-degree swing, as a number, caught by putting the `% TWO_PI`
back.

## 2. The bumpiness is vertical, and it is measurable

The route's z is interpolated linearly along each segment, so the vertical
*position* is continuous while the vertical *speed* is not: it changes
abruptly at every waypoint, and at 1400 units a second a waypoint arrives
about once a second. Measured over six real routes, the worst of those steps
is **13.4 units of vertical speed per frame** — a jolt once a second.

A first-order ease on the vertical only. x and y keep following the path
exactly, because smoothing those would cut corners, which is a worse fault
than a jolt. The constant is a trade and was measured as one:

| tau (s) | worst jolt | worst lag behind the path |
|---:|---:|---:|
| 0.00 | 13.36 u/frame | 0 |
| 0.05 | 4.24 | 34 |
| **0.10** | **2.34** | **73** |
| 0.25 | 0.97 | 170 |
| 0.80 | 0.30 | 393 |

0.10 cuts the jolt 5.7× for 73 units of lag at the very steepest point of the
steepest route — under 6% of the strider's own 1284-unit height, about a metre
on an eighteen-metre animal, and only where the ground is at its worst. It is
clamped at 150 units as well as eased, so a cliff cannot leave the strider
hanging; past the clamp the vertical tracks the path and the jolt returns,
which is the right failure.

## 3. Boats: boarding was throwing, nine times in your log

Not something you reported, but it is in there:

```
Global[.../boats_global.lua] eventHandler[WWBoats_RequestBoard] failed.
Lua error: Path should start with 'meshes\'
  [C]: in function 'createRecordDraft'
  boats_global.lua:130: in function 'copyRecordFor'
```

`copyRecordFor` passed the model path bare, on a note in `api-findings` saying
`createRecord` adds the `meshes\` prefix itself. It does not, on this build —
and it does not merely store the wrong thing, it **throws**. Boarding a
rowboat failed outright. The file even had a diagnostic for "if the engine
stored something else", which could never run because nothing after the throw
does.

Forward slashes are fine despite the message naming a backslash: Caravans has
spawned its vehicle from `'meshes/' .. mesh` since 22 October and the
activator renders.

**The harness had implemented the belief rather than the engine** — its
`createRecord` mock quietly prepended `meshes\` to whatever it was given, so
the bug was invisible to 62 passing assertions. The mock now raises the
engine's own error on an unprefixed path, and against the unfixed code the
suite stops with `Path should start with 'meshes\'`.

## 4. The lag spikes approaching the driver are not WhyWalk

Nothing in Caravans runs per frame outside a journey — the global's `onUpdate`
returns on its first line without a session, and the player script has no
frame handler.

What the log does show is animation loading. Bucketed by five seconds:

```
06:05  ████████████████████████████████████████ 400
07:50  ████████████ 128
08:25  ███████████████████████████ 272
11:00  ██████████████████████ 228
```

Those bursts are cell loads and NPC model builds, and the 07:50 one sits right
on the `selvil sareloth` line — the moment you walked up to a caravaner in a
town. Each NPC build is printing eight warnings:

```
Warning: addAnimSource: can't find bone 'bip01 tail'  in meshes/xbase_anim.nif
  (referenced by animations/xbase_anim/xfarmer2.kf)
... and 'tail1', 'tail2', 'tail3', for xfarmer2.kf and xcleaner.kf
```

87 of each, so around 700 log writes per crowded cell. Two animation packs
(`xfarmer2.kf`, `xcleaner.kf`) reference tail bones that `xbase_anim.nif` does
not have, and every NPC that loads them pays for the failed lookups and the
logging. Fixing or dropping those two files is the lever; it is not a WhyWalk
problem but it is making your towns slower.

The vertical test asserts the *ratio*, not the constant: smoothing must cut
the worst jolt at least fourfold while costing under a tenth of the strider's
height in lag, and the clamp must stay a backstop rather than the mechanism.
Changing tau has to keep clearing all three.

## What to look for

1. **Turns.** A 20-degree turn should be a 20-degree turn, and crossing north
   should be unremarkable. This is the one I expect to change the ride most.
2. **The drift after a turn** — some of it was the spin unwinding. If a lean
   is still there, the question from last time stands: is it on the straights
   too, or only in bends?
3. **Bumpiness**, which should be about a fifth of what it was.
4. **Boarding a rowboat**, which was not working at all.
